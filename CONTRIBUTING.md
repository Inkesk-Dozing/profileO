# Contributing Guidelines

We welcome contributions to the portfolio repository. Please adhere to the following standards to maintain code quality and structural integrity.

## Pull Request Process

1. Fork the repository and create a descriptive feature branch from `main`.
2. Keep edits focused. Do not combine multiple unrelated changes in a single pull request.
3. Validate that your changes run locally without exceptions or linting warnings.

## Code Quality Standards

- **HTML/CSS/JS**: Keep scripts modular and ensure semantic markup is used.
- **Python (if applicable)**: Code should conform to PEP 8 standards. Use standard formatters such as Black.
- **Linting**: Run regular formatting checks to prevent styling drift.

## Commit Messages

We enforce Conventional Commits formatting:
- `feat:` for new features
- `fix:` for bug fixes
- `docs:` for documentation updates
- `style:` for changes that do not affect code logic (formatting, spacing)
- `refactor:` for code changes that neither fix a bug nor add a feature
- `test:` for adding or modifying tests
- `chore:` for general build tasks or configurations
